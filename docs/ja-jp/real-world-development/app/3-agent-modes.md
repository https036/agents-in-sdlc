プロジェクトに小さな機能を追加しましたが、大きな変更には、さらに堅実なプロセスが必要です。GitHub Copilot app は組織の既存の流れに沿って作業できるように設計されており、適切なものを適切な方法で構築できます。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスを進めます。issue を使って新機能を作成するところから始め、コードが有効で機能が期待どおりに動作することを確認し、最終的にプロジェクトへマージします。

> [!NOTE]
> 機能のワークフローを続ける間、同じセッションを使います。通常はファイルの種類ごとに異なるセッションや PR を使いますが、ここでは中心的な概念に集中できるよう簡略化します。

このレッスンでは、次のことを行います。

- GitHub issue から新しいエージェント セッションを開始します。
- **Plan** モードで要件を定義します。
- **Autopilot** モードで新しい機能を実装します。
- コードをレビューします。
- ブラウザー Canvas で機能を手動検証します。

機能の作業を続けながら、リポジトリの指示を更新し、既存の quality-checks スキルをカスタマイズし、MCP による検証を追加して、QA エージェントを作成し、機能 PR を作成します。

## シナリオ

Tailspin Toys のカタログが増え、訪問者がカテゴリと出版社でゲームを絞り込める機能が必要です。バックログの issue には機能の概要がありますが、カテゴリを組み合わせる方法など、コーディング前に合意が必要な詳細があります。Plan モードで決定事項を整理してから、範囲を限定した実装を Autopilot に依頼します。

## 背景

AI コーディング エージェントを開発フローに導入しても、基本は変わりません。むしろ、基本はさらに重要になります。多くの開発者は、次のような流れで作業します。

1. 必要な作業の詳細が記載された issue を開きます。
2. 構築する内容の計画を作成します。
3. コードを構築してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーション プロセスが成功したら、コードをマージします。

> [!NOTE]
> 正確な手順はチームや組織によって異なりますが、多くの場合は上記に似た流れです。

この標準的なアプローチを守ると、AI が生成したコードが要件を満たし、人が作成したコードと同じ検証プロセスを通るようになります。

## セッション モード

**セッション モード**は、エージェントの自律性を制御します。プロンプト フィールドの下にあるドロップダウンで設定し、いつでも変更できます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、続行前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。実行前に計画をレビューして承認します。
- **Autopilot**: エージェントは入力を待たずに、コードを書き、テストを実行して、作業を自律的に繰り返します。

まず Plan モードで計画を確認し、その後 Autopilot で実装します。

## issue からセッションを開始する

作業を始める前に、星評価の PR がマージされ、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** で Tailspin Toys リポジトリ フォルダーを選択し、リポジトリ上部のナビゲーションで **Issues** を選択します。すでに登録されている **Allow users to filter games by category and publisher** を開きます。新しい issue を作成する必要はありません。
2. **New session** を選択し、更新された `main` に基づく **new working tree** を選択します。

    ![GitHub Copilot app の issue ビューで、New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. issue がセッションに添付されていることを確認し、モード セレクターで **Plan** を選択します。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` を実行するよう依頼します。ターミナルでは動作するのにセッション内で動かない場合は、app の PATH またはバージョン マネージャーの設定を確認し、app を完全に終了してから再度開きます。失敗した操作とチェックを再試行してください。エージェントが npm を見つけられないという理由だけで、npm を再インストールしないでください。

## フィルター機能を計画する

計画を立てると、Copilot がコードを書く前にアプローチを確認できます。issue から始めたため、Copilot は機能のリクエストをすでにコンテキストとして把握しています。次の内容を送信します。

```plaintext
Build this feature.
```

Copilot の質問に回答し、issue の受け入れ条件と計画を照らし合わせます。カテゴリと出版社による絞り込み、アクセシブルなコントロール、データ アクセスの変更、テストが含まれていることを確認してください。複数のカテゴリをどう組み合わせるか、一致するゲームがない場合にどうするかなど、不明確な動作について話し合います。

計画には、プロジェクトの既存ツールを使った lint、ユニット テスト、E2E テスト、型チェックを含めます。フィルター機能の実装とテストに範囲を絞り、品質ワークフローが完了してから PR を作成します。計画の変更は承認前に依頼し、後の検証に使えるよう issue の URL と合意した追加の決定事項を控えておきます。

## Autopilot を明示的に承認する

計画に納得したら、**Approve and implement this plan**、または使用しているバージョンで同等の表示を選択します。承認によってモードも切り替わると思い込まず、現在のモードを確認してください。モード表示に **Autopilot** が表示されていることを確認します。

Copilot が実装を開始します。作成した計画に沿って作業し、コードを生成してテストも実行しながら、処理を繰り返します。

> [!NOTE]
> 承認すると、実装がすぐに始まる場合があります。先に計画をレビューしてください。Copilot が依存関係の不足やポート競合を報告した場合は、チェックを完了とみなす前にセットアップの問題を解決します。自分で起動したサーバーだけを停止してください。

## 実装をレビューして検証する

生成されたコードは、ほかのコードと同じようにマージ前にレビューします。コードを確認し、サイトを実行して問題がないことを確認しましょう。

1. **Changes** を開き、フィルター機能の実装とテストを確認します。
2. 複数カテゴリや出版社の組み合わせも含め、変更を issue と承認済みの追加決定事項に照らし合わせます。変更が既存のリポジトリの指示に従っていることも確認します。
3. lint、ユニット テスト、E2E テスト、型チェックの結果を確認します。スキップされたチェックは成功ではありません。
4. 実装を採用する前に失敗を解決し、影響するチェックを再実行します。Playwright の E2E 設定はプレビューをビルドして配信し、ローカル サーバーを再利用する場合があります。テストしているのが以前のレッスンではなく、この worktree のサーバーであることを確認してください。

## 新しい機能を確認する

コードに問題がないように見えても、実際に動くでしょうか。前と同様にアプリを起動し、ブラウザー Canvas でサイトを開きます。

1. 次のプロンプトで、アプリを起動してブラウザー Canvas にページを開くよう Copilot に依頼します。

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザー ウィンドウが開きます。
3. カテゴリを選択し、結果がそのカテゴリと一致することを確認します。フィルターを解除し、次に出版社を選択して、結果がその出版社と一致することを確認します。
4. カテゴリと出版社のフィルターを組み合わせ、結果を issue と承認済みの計画に照らし合わせます。複数のカテゴリに対応している場合は、合意した組み合わせの動作も確認します。
5. 結果が一致しない組み合わせを試し、空の状態を確認します。フィルターを解除またはリセットして、すべてのゲームが再表示されることを確認します。
6. 確認が終わったら、次のプロンプトを使い、このセッションで起動した開発サーバーを停止するよう Copilot に依頼します。

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 次のレッスンのためにこのセッションを残す

フィルター機能の PR は、まだ作成もマージもしないでください。レッスン 4 から 8 まで、このセッション、worktree、ブランチを使います。次はカスタム指示をフィルター機能のコードに適用し、さらにスキルと QA の改善を追加してから、レッスン 8 でまとめた PR を作成してマージします。開発サーバーを停止した後は、セッションをそのままにしてかまいません。次のレッスンで同じセッションに戻ります。
