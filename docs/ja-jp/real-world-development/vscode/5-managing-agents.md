GitHub Copilot を agent mode で使うと、コードベースを調査し、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、この作業がマシン上でリアルタイムに進むため、すべてのツール呼び出しとファイル編集を確認できます。差分をインラインでレビューして個々の変更を採用または取り消し、エディターを離れずにフォローアップ プロンプトを送信して、会話を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッション中にエージェントを誘導し、ハイ コントラストに加えてライト モードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の要望がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加したいとのことです。新しい会話を始める代わりに、進行中のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが調査するファイル、実行するコマンド、提案する編集など、各手順を確認できます。ファイルの編集は差分と **Keep** / **Undo** コントロールとともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
    - **Keep** を選択して変更を採用します。
    - **Undo** を選択して変更を取り消し、エージェントに別の方法を試してもらいます。
4. チャット上部の **Files changed** インジケーターを開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツール呼び出し（たとえばターミナル コマンドの実行）が許可を求める場合、エージェントは停止して **Allow** プロンプトを表示します。実行を許可するコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に変更内容の概要が表示されます。

## エージェントを誘導してライト モードを追加する

ハイ コントラスト モードが追加されたら、同じ会話を続けてライト モードの切り替えを追加します。同じチャット セッションを使うため、エージェントはこれまでに変更したコンポーネントやスタイルの方針、ローカル ストレージの使い方を把握しています。

1. Copilot Chat の入力欄で、次のフォローアップ プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライト モードの追加を提案します。
3. これまでと同じように新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合（たとえば、切り替え UI のリファクタリングが希望と異なる場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を追加して再度依頼します。

> [!TIP]
> 進行中のセッションを誘導すると、新しい会話を始めるより効率的です。フォローアップで調整を依頼します（「CSS を簡潔にして、セレクターを重複させず CSS 変数を使う」など）。方向を修正したり（「3 つ目のトグルは追加せず、ライト モードを既存の設定パネルに統合する」など）、範囲を広げたり（「両方のトグルにキーボード ショートカットも追加する」など）できます。

## 作業内容をレビューする

作業をコミットする前に、エージェントが変更したファイル全体を確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更ファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれているはずです。
3. 変更ファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージによる設定の保持など、アクセシビリティ エージェントのガイドラインが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンでブランチを公開します。

## まとめと次のステップ

Copilot Chat agent mode を使って進行中のセッションを監視、誘導し、ファイル編集ごとに確認して採用または取り消し、コンテキストを失わずにフォローアップを送って作業を拡張しました。

このレッスンでは、次のことを学びました。

- エージェントの作業をリアルタイムで監視する
- 個々の編集を採用または取り消す
- セッション中にフォローアップを送り、エージェントを誘導する

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開します。また、このラボ全体でローカル カスタム エージェントが行った変更を確認します。
